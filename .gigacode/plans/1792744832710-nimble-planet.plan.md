# План завершения проекта DPServiceCenterCRM

## Обзор
Текущее состояние: доменная модель (~40 классов) + HealthController + 1 тест.
Цель: полный CRUD, JPA, Flyway, Security, DTO, Swagger, тесты.

## Шаг 1: JPA-аннотации для всех сущностей

### 1a. BaseEntity + BaseEntityListener
**Файлы:**
- `entity/common/BaseEntity.java` — добавить `@MappedSuperclass`, `@Id`, `@GeneratedValue`, `@Version`, `@Column`, сеттеры
- `entity/common/BaseEntityListener.java` (новый) — `@PrePersist`, `@PreUpdate` для createdAt/updatedAt

### 1b. Все entity-классы — добавить @Entity, @Table, @Column, @Enumerated, @OneToMany/@ManyToOne

| Entity | Таблица | Ключевые связи |
|--------|---------|----------------|
| `Client` | `clients` | 1→N `Order` |
| `Order` | `orders` | M→1 `Client`, 1→N `OrderWork`, `Payment`, `Document`, `Notification`, 1→1 `Warranty`, 1→N `Approval` |
| `OrderWork` | `order_works` | M→1 `Order` |
| `OrderEvent` | `order_events` | M→1 `Order` (сохраняется сервисом отдельно) |
| `Payment` | `payments` | M→1 `Order` |
| `Part` | `parts` | — |
| `StockMovement` | `stock_movements` | M→1 `Part` |
| `Document` | `documents` | M→1 `Order` |
| `DocumentTemplate` | `document_templates` | уникальный constraint(code, version) |
| `Notification` | `notifications` | — |
| `NotificationTemplate` | `notification_templates` | уникальный constraint(code, version) |
| `Attachment` | `attachments` | полиморфный: ownerType(VARCHAR) + ownerId(BIGINT) |
| `User` | `users` | уникальный username |
| `ServiceCenter` | `service_centers` | уникальный inn |
| `Location` | `locations` | M→1 `ServiceCenter` |
| `Warranty` | `warranties` | M→1 `Order` |
| `PriceListItem` | `price_list_items` | M→1 `ServiceCenter` |

**Паттерн для всех:**
- `@Where(clause = "deleted_at is null")` — soft delete
- `@Enumerated(EnumType.STRING)` — для всех enum-полей
- `@Column(precision = 15, scale = 2)` — для BigDecimal
- `FetchType.LAZY` — для всех @ManyToOne
- `CascadeType.ALL, orphanRemoval = true` — для 1→N коллекций

- `OrderCreateRequest`, `OrderResponse`

## Шаг 5: Service слой

**Пакет:** `com.ibigboss.crm.service`

Сервисы с `@Transactional`:

- `OrderService` — CRUD + changeStatus + approveConditions + finalizePricing + markPickedUp

- `DocumentService` — create, reprint, sign, void
- `NotificationService` — create, send flow (PENDING → SENT → DELIVERED → READ)
- `AttachmentService` — upload metadata
- `WarrantyService` — create warranty based on order completion
- `ApprovalService` — create, approve, reject, expire
- `PricelistService` — CRUD PriceListItem
- `ServiceCenterService` — CRUD + nextOrderNumber / nextDocumentNumber

## Шаг 7: Spring Security

**Файлы:**
- `com.ibigboss.crm.config.SecurityConfig.java` — конфигурация
- `com.ibigboss.crm.security.CustomUserDetailsService.java` — loadUserByUsername
- `com.ibigboss.crm.security.AuthResponse.java` — DTO для auth

Настройки:
- BCryptPasswordEncoder для хеширования паролей
- Session-based authentication (не JWT — проще для internal CRM)
- CSRF включён
- Role-based access:
  - RECEIVER: может создавать/читать заказы, работать с клиентами
  - MASTER: может работать со своими заказами, order works
  - ADMIN: полный доступ + управление пользователями, прайс-листом
  - DIRECTOR: полный доступ + финансовая аналитика
- `/api/health` и `/swagger-ui/**` — публичные
